1. What is a RIDE session?

When you record a ride, every data point from your bike and heart-rate monitor is kept: power, cadence, speed, distance, trainer resistance, heart rate and the RR intervals between heart beats, plus every start, pause, resume, lap and stop. RIDE is the compact binary format that holds all of this without losing anything, so a session can be saved, moved to another application, edited and saved again.

.ridefile extension
~120 kB / hourat 1 sample per second
Checksumdetects damaged or incomplete data
Base64 textfor copy/paste and text-only storage

Use TCX when you want to upload a ride to Strava, Garmin Connect or TrainingPeaks. Use RIDE when you want to keep the complete raw data for your own applications.

2. Saving a session

Any Session (for example tracker.session) can be turned into RIDE data:

import { SessionTracker } from './src/session_tracker.module.js';

const tracker = new SessionTracker({ bike, heartRateMonitor });
// … tracker.start(), tracker.lap(), tracker.stop() …

tracker.session.downloadBinary();          // saves e.g. "2026-10-16_1830_ride.ride"
const bytes = tracker.session.toBinary();  // Uint8Array – for uploads and databases
const text  = tracker.session.toBase64();  // string – for clipboard, JSON documents, localStorage

3. Copy & paste between applications

The base64 text is plain ASCII, so it survives e-mail, chat, clipboards and text fields. Line breaks and spaces added along the way are ignored when reading.

// Application A
await navigator.clipboard.writeText(session.toBase64());

// Application B – accepts base64 or JSON
import { Session } from './src/session_tracker.module.js';
const session = Session.parse(pastedText);

The text starts with UklERQ (base64 for "RIDE"), which makes RIDE data easy to recognise.

4. Loading and editing a session

const session = await Session.fromFile(fileInput.files[0]);  // .ride, base64 text or JSON
// or: Session.fromBinary(bytes), Session.fromBase64(text)

session.meta.title = 'Tuesday intervals';   // free-form metadata
session.insertLap(15 * 60 * 1000);          // add a lap marker 15 minutes in
session.removeLap(2);                       // merge lap 2 into lap 1
session.crop(60_000, session.duration - 30_000); // cut the warm-up minute and the last 30 s

console.log(session.getStats(), session.getLapStats());
session.downloadBinary();                   // save the edited version
session.downloadTCX();                      // or export it for Strava
OperationWhat it does
metaAny JSON object: title, notes, athlete data, game level, …
insertLap(t)Adds a lap marker at t ms after the start; returns the new lap index
removeLap(i)Removes the marker that starts lap i (≥ 1)
crop(from, to)Keeps only that part of a stopped session; times and distance restart at 0
bikeSamples, heartRateSamples, eventsPlain arrays you can change directly – call session.invalidate() afterwards so statistics are recalculated
clone()Independent copy, e.g. to keep the original while editing

Saving, loading and saving again produces identical bytes, so repeated edits never degrade the data.

5. Storing sessions in a database

Store the bytes in a binary column (BYTEA in PostgreSQL, BLOB in MySQL/SQLite) and copy the values you want to search or sort by into normal columns:

const stats = session.getStats();
await fetch('/api/sessions', {
    method: 'POST',
    headers: { 'Content-Type': 'application/octet-stream',
               'X-Started-At': new Date(session.startTime).toISOString(),
               'X-Distance-M': String(stats.distance) },
    body: session.toBinary(),
});

Text-only stores (document databases, localStorage) can hold session.toBase64(). In the browser, IndexedDB stores the Uint8Array directly. A back end that is not JavaScript can read the data with the short Python decoder in the format specification.

6. What is inside the file

A fixed header, four chunks and a checksum. All numbers are little-endian. The complete byte-level description is in binary-format.md.

Header · 24 bytes"RIDE", version, header size, start time, end time
METAJSON metadata: title, notes, device names, your own fields
EVNT · 5 bytes / eventstart, pause, resume, lap, stop with times
BIKE · 4 + 4 bytes per channel / samplepower, cadence, speed, distance, resistance
HRTR · 7 + 2 bytes per RR / sampleheart rate and RR intervals – its own timeline
CRC-32 · 4 byteschecksum of everything above

Heart rate has its own timeline because heart-rate straps and bikes send data at different moments. Nothing is lost by forcing one onto the other; the two are only combined when exporting to TCX.

8. Troubleshooting

MessageCause and fix
Not a RIDE sessionThe data does not start with "RIDE". Check that the whole text was copied, or that the file is a .ride file and not a .tcx.
Checksum mismatchPart of the data is missing or changed – usually a clipped copy/paste. Copy it again. For recovery, Session.fromBinary(bytes, { verifyChecksum: false }) skips the check.
Unsupported RIDE format versionThe file was written by a newer version of the library. Update the library.
The text is not valid base64The pasted text contains other characters, for example quotes or a message around it.
